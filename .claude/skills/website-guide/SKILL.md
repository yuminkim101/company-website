# 웹사이트 페이지 제작 가이드

프로젝트 규칙의 기준은 루트의 `CLAUDE.md`, 콘텐츠의 유일한 출처는 `00_회사소개.md`다. 둘을 먼저 읽고 시작한다.

## 제작 절차

### 1. 준비
1. `CLAUDE.md`와 `00_회사소개.md`를 읽는다.
2. 만들 페이지와 담당자를 확인한다: `index.html`(회사 소개), `service.html`(서비스 소개 + 카테고리 이모지 미니게임), `location.html`(오시는 길). 문의하기 페이지는 없다.
3. 이미 만들어진 페이지가 있으면 헤더·푸터·`css/style.css`의 변수와 클래스를 먼저 살펴 재사용한다.

### 2. 콘텐츠 정리 (코딩 전)
1. 페이지에 넣을 내용을 `00_회사소개.md`에서 골라 목록으로 만든다.
2. 문서에 없는 항목(주소, 연락처, 운영시간, 지도, 이미지 등)을 따로 표시한다. **사실처럼 채우지 않고** 자리표시자 + `<!-- TODO: 확인 필요 -->`로 남긴다.
3. 외부 공개에 부적합한 내부 정보(분기 목표, 팀별 고민, 광고 성과, 리뷰·CS 이슈 등)는 제외한다.
4. 사용자에게 섹션 구성(순서와 제목)을 짧게 보여주고 확인받는다.

### 3. 구조 작성 (HTML)
1. 공통 뼈대(`lang="ko"`, charset, viewport, title, description)를 넣는다.
2. 공통 헤더/내비게이션/푸터를 넣고 현재 페이지에 `aria-current="page"`를 표시한다.
3. `main` 안에 섹션별로 시맨틱 마크업을 작성한다. 내용은 정리한 목록 그대로 옮긴다.

### 4. 스타일 작성 (CSS)
1. 공통 변수와 스타일은 `css/style.css`, 페이지 전용은 `css/<페이지명>.css`에 쓴다.
2. 모바일 화면부터 작성하고 `min-width` 미디어쿼리로 태블릿·데스크톱을 확장한다.
3. 새 색상·간격은 하드코딩하지 말고 `:root` 변수에 추가해서 쓴다.

### 5. 동작 작성 (JavaScript, 필요한 경우만)
1. 꼭 필요한 동작만 `js/main.js` 또는 `js/<페이지명>.js`에 쓴다. (예: 모바일 메뉴 토글, 서비스 페이지 미니게임)
2. `<script defer>`로 불러오고, 인라인 이벤트 속성을 쓰지 않는다.

### 6. 검수와 마무리
1. 아래 체크리스트를 항목별로 직접 확인한다.
2. 통과하지 못한 항목은 고치고 다시 확인한다.
3. 결과를 보고할 때 확인한 항목, 확인하지 못한 항목, 남은 TODO(문서에 없는 정보)를 구분해서 알린다. 확인하지 않은 것을 통과했다고 쓰지 않는다.

## 검수 체크리스트

### 콘텐츠 정확성
- [ ] 모든 사실(수치, 날짜, 이름, 서비스 설명)이 `00_회사소개.md`와 일치한다
- [ ] 문서에 없는 정보를 지어내지 않았고, 비어 있는 곳은 자리표시자 + TODO로 표시했다
- [ ] 수치에 기준 시점이 붙어 있다 (예: 2026년 9월 기준)
- [ ] 내부 정보(분기 목표, 팀별 고민, 광고·리뷰·CS 이슈)가 노출되지 않는다
- [ ] 오탈자·맞춤법을 확인했고, 존댓말 등 어조가 페이지 간 일관된다

### HTML
- [ ] `lang="ko"`, charset, viewport, `title`, `meta description`이 있다
- [ ] `h1`이 하나이고 제목 단계가 건너뛰어지지 않는다
- [ ] `header` / `nav` / `main` / `footer` 구조를 지켰다
- [ ] 모든 이미지에 `alt`가 있다
- [ ] 폼이 있다면 입력마다 `<label>`이 연결되어 있다
- [ ] 인라인 `style`, 인라인 이벤트 속성이 없다
- [ ] 깨진 링크가 없고, 3개 페이지 간 내비게이션이 모두 이동된다

### CSS
- [ ] 색상·글꼴·간격이 CSS 변수를 통해 쓰였다
- [ ] 클래스명이 kebab-case이고 `id` 선택자 스타일링, `!important`가 없다
- [ ] 모바일(약 360px)에서 가로 스크롤 없이 읽힌다
- [ ] 태블릿·데스크톱 폭에서도 레이아웃이 깨지지 않는다
- [ ] 글자와 배경의 대비가 충분하다

### JavaScript
- [ ] `var`와 `console.log`가 남아 있지 않다
- [ ] 브라우저 콘솔에 오류가 없다
- [ ] JS를 꺼도 콘텐츠를 읽을 수 있다 (핵심 내용이 JS에 의존하지 않는다)
- [ ] 서비스 미니게임: 이모지 버튼(`aria-label` 있음)으로 열리고, Esc·닫기 버튼으로 닫히며, 키보드·터치로 조작된다
- [ ] 미니게임이 없어도(JS 꺼짐) 카테고리 이름과 설명이 읽힌다, 게임 문구에 지어낸 사실이 없다

### 접근성·품질
- [ ] 키보드(Tab)만으로 메뉴·링크·폼을 조작할 수 있고, 포커스가 보인다
- [ ] 링크·버튼 텍스트만으로 목적을 알 수 있다 ("여기 클릭" 금지)
- [ ] 이미지 용량이 과하지 않고 파일명이 규칙(영문 소문자·하이픈)을 지킨다

### 협업
- [ ] 담당 페이지 외 파일을 수정하지 않았다 (공통 파일을 수정했다면 팀에 공유했다)
- [ ] 헤더·푸터가 다른 페이지와 동일하다
- [ ] 파일명·폴더 위치가 `CLAUDE.md`의 파일 구조와 일치한다
